## Что мы делаем

Строим MVP приложения **Godex Label Printer** — программу для печати этикеток из Excel на принтерах Godex.

**Ключевые технические решения (зафиксированы, не пересматриваем без явного согласия):**

- Стек: **C# / .NET 8 + WPF**
- UI: **WPF-UI (lepoco)** для Fluent-стиля
- MVVM: **CommunityToolkit.Mvvm**
- Excel: **ClosedXML**
- Штрихкоды в превью: **ZXing.Net**
- Печать: **прямая генерация EZPL и отправка в принтер** (raw через WinAPI `OpenPrinter`/`WritePrinter` для USB; `TcpClient` на порт 9100 для сетевых). Печать через штатный Windows-драйвер в MVP не делаем.
- Формат шаблона: **JSON**
- Единицы измерения внутри программы: **миллиметры**; конвертация в точки принтера (dots) происходит только при генерации EZPL с учётом DPI шаблона (203 DPI = 8 dots/mm, 300 DPI = 12 dots/mm)
- Структура решения: несколько проектов — `Core`, `Excel`, `Ezpl`, `Printing`, `App` (WPF)

## Правила по EZPL

- Все команды принтеру формируем строго по спецификации `EZPL_EN_J_20180226.pdf`. Если сомневаешься в синтаксисе — открой PDF и сверься, не угадывай
- В коде генератора EZPL каждую команду сопровождай комментарием со ссылкой на страницу или раздел мануала (например, `// ^Q — Label length, EZPL manual p.10`)
- Все координаты и размеры в модели шаблона — **в миллиметрах** (`double`), с явным суффиксом `Mm` в именах свойств (`XMm`, `YMm`, `WidthMm` и т.д.), чтобы случайно не перепутать с точками
- Пересчёт mm → dots делаем в одном месте (утилита `MmToDots(double mm, int dpi)`), не размазываем по коду

## Правила по коду

- **Именование:** классы, свойства, методы — по-английски (`LabelTemplate`, `PrintJob`); пользовательские тексты, комментарии, сообщения об ошибках — по-русски
- **Никакого legacy .NET Framework** — только .NET 8, современный C# (nullable enabled, file-scoped namespaces, `record` где уместно)
- **MVVM жёстко:** никакой логики в code-behind окон, кроме подписки на события UI-контролов, где без code-behind не обойтись (drag&drop на Canvas). Всё остальное — во ViewModel через команды и биндинги
- **DI** через `Microsoft.Extensions.DependencyInjection` — сразу с первого этапа
- **Логирование** через Serilog — тоже с первого этапа, чтобы потом не переделывать
- **Валидация ввода** — везде, где пользователь вводит числа (размеры этикетки, координаты, DPI)
